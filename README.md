# 芯栈 Lab · 实验室管理系统（js）

现已包含 Node.js 后端和 SQLite 数据库，默认通过同源相对地址 `./api` 访问（子目录部署自动使用 `/lab/api`）。老师、负责人、学生账号，以及模块、借还、请假、比赛与操作记录均由服务器保存；浏览器不保存正式账号密码或业务数据库。

**已于 2026-10-26 部署到腾讯云：[打开云端系统](https://119.91.63.248/lab/)。** 正式账号和业务数据保存在服务器；本地运行的数据仍在本机。

## 本地启动

需要 Node.js **24.13+**，无第三方运行时依赖，无需安装 npm 包。

```sh
npm run init-admin  # 创建首位 teacher 老师，终端仅显示一次随机密码
npm start           # http://127.0.0.1:4173
npm test            # 前端和后端集成测试
```

初始化只有一位老师、空业务数据，不自动创建原演示账号或示例比赛。老师登录后在“成员管理”创建老师、负责人和学生账号。在“个人中心”可修改自己的密码，修改后所有设备会话失效。再次运行初始化不会覆盖现有数据。

如需指定初始化账号和姓名，可设置 `ADMIN_USERNAME`、`ADMIN_NAME` 环境变量。不要把真实密码写进代码或提交到 Git。可复制 `.env.example` 为 `.env` 配置端口和数据库路径。

数据库默认位于 `data/lab.sqlite`，启动备份及每日备份位于 `data/backups/`，这些路径已被 Git 忽略。启动脚本为 Node 后端，不能再使用 Python 静态服务器代替。

## 云服务器部署

目标服务器为 `119.91.63.248`，应用目录 `/opt/xinzhan-lab`，数据库 `/var/lib/xinzhan-lab/lab.sqlite`。使用独立 Node.js v24.22.1 运行包、系统用户及 `xinzhan-lab.service`，开机自动启动。完整运维步骤见[腾讯云部署指南](deploy/README.md)。

现有 Nginx 将 `/lab/` 转发到本机 4173；原 Sub2API 继续使用自己的目录、容器、数据库和 8080 端口。两者共用已有 HTTPS 证书，新系统没有额外开放公网端口。

初始老师用户名为 `teacher`，随机初始密码及访问地址保存在项目根目录 `云端登录信息.txt`（仅本机、已忽略 Git）。其他正式账号由老师在成员管理创建。

## 功能与权限

| 功能 | 指导老师 | 负责人 | 学生 / 普通成员 |
| --- | --- | --- | --- |
| 查看成员公开状态、库存及比赛 | 可以 | 可以 | 可以 |
| 创建和管理账号 | 各角色，不能修改自身角色 | 仅普通成员 | 不可以 |
| 修改个人资料、状态、密码 | 本人 | 本人 | 本人 |
| 管理资产、维修、报废及比赛 | 可以 | 可以 | 不可以 |
| 提交借用 / 请假、申请归还 | 本人 | 本人 | 本人 |
| 审批、发放、验收 | 他人 | 他人且为普通成员 | 不可以 |

服务端强制执行权限、字段和状态校验，不依赖浏览器隐藏按钮。请假原因、审批意见、联系方式、他人借用用途按角色裁剪。密码通过随机盐加 scrypt 哈希保存，不回传给浏览器。

借用流程：待审批 → 待发放 → 使用中 → 待确认归还 → 已归还。审批不占库存，发放时检查并占用；归还申请不释放库存，整单验收后释放，损坏设备进入维修。状态、维修记录与日志同一事务提交，防止多人同时发放同一设备。

请假通过后在有效时段自动覆盖工作状态，结束后恢复成员自己设置的状态。页面空闲时每 30 秒从服务器同步，编辑表单时暂缓自动同步；这不是即时消息推送。

## 数据与访问保护

- 正式登录使用 HttpOnly Cookie，12 小时到期；HTTPS 生产模式加 Secure。
- 登录错误按账号和连接来源限流，限制记录持久保存。
- 写接口需要同源校验和 `X-Lab-Request: 1`，不接受浏览器跨站写入。
- 修改密码、账号角色、登录账号或停用账号会撤销相关会话。
- 静态资源采用允许列表，数据库、备份、环境文件、Git 和后端代码不能通过网页下载。
- 服务启动和每 24 小时创建经完整性检查的备份；同机备份需要另行复制到异地。
