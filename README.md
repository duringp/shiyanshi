# 芯栈 Lab · 嵌入式实验室管理系统

面向指导老师、负责人和普通成员的实验室管理前端，集中管理人员状态、嵌入式模块、借还流程与比赛安排。

**当前为可运行的前端演示，默认数据保存在浏览器中，尚未连接阿里云后端。** 项目使用原生 HTML、CSS、JavaScript，无第三方依赖、CDN 或构建步骤；部署时需同时保留 `index.html` 和 `src/`。

## 快速开始

需要现代浏览器和 Python 3；运行自动化测试另需 Node.js 20+。无需执行 `npm install`。

首次下载项目：

```sh
git clone https://github.com/duringp/shiyanshi.git
cd shiyanshi
python3 -m http.server 4173 --bind 127.0.0.1
```

已有项目时，在项目目录执行最后一条命令即可。服务启动后打开 [本地页面](http://127.0.0.1:4173/)，使用下方账号登录。关闭服务终端或按 `Ctrl+C` 可停止预览。

其他启动方式：安装 Node.js 后可运行 `npm start`；macOS 可双击 [启动预览.command](启动预览.command)。脚本检测已有预览服务，或在当前目录启动服务。

也可直接打开 `index.html`，但建议固定使用 HTTP 地址测试。不同协议、主机名或端口对应不同存储环境，`localhost` 和 `127.0.0.1` 的演示数据不会自动共享。

## 功能与权限

### 页面功能

| 页面 | 已实现内容 |
| --- | --- |
| 工作台 | 人员与库存统计、逾期和审批待办、近期比赛、操作动态 |
| 成员管理 | 搜索筛选、分页、成员详情、创建账号、编辑资料、启用和停用 |
| 请假管理 | 提交申请、审批、拒绝、撤销待审批申请、有效时段状态显示 |
| 模块管理 | 一物一码、型号库存、使用者与状态、维修、报废、历史记录 |
| 借用与归还 | 多模块申请、审批、实物发放、归还申请、验收与损坏送修 |
| 比赛管理 | 报名与比赛时间、自定义流程节点、参赛须知、官方链接、归档与恢复 |
| 操作记录 | 查看业务流转记录，按身份控制私密内容显示 |
| 个人中心 | 个人资料、工作状态、演示身份切换与恢复初始数据 |

初始数据包含 8 位成员、18 件实物模块、13 种型号、6 类模块及 3 场示例比赛。界面支持响应式导航、中文搜索、表单校验、状态提示和键盘操作。

### 角色权限

| 操作 | 指导老师 | 负责人 | 普通成员 |
| --- | --- | --- | --- |
| 查看公开成员状态、模块与比赛 | 可以 | 可以 | 可以 |
| 修改本人资料和工作状态、提交本人申请 | 可以 | 可以 | 可以 |
| 创建和管理成员账号 | 可管理各角色 | 仅普通成员 | 不可以 |
| 设置成员角色 | 可以，不能修改自身角色 | 不可以 | 不可以 |
| 管理模块、维修、报废及比赛 | 可以 | 可以 | 不可以 |
| 审批、发放、验收 | 他人的申请 | 他人且申请人为普通成员 | 不可以 |
| 查看请假原因和意见 | 本人及有审批权限的申请 | 本人及有审批权限的申请 | 仅本人 |

所有角色都不能审批自己的申请。停用成员须先完成其未结束的借用和请假业务，不能停用自己；停用和报废均保留历史。完整规则见 [API 权限约定](API.md#权限与可见范围)。

## 常用操作

### 创建成员账号

1. 使用 `teacher` 或 `manager` 登录，进入“成员管理”→“新增成员”。
2. 填写姓名、学号 / 工号、所属小组和登录账号，选择权限允许的角色。
3. 设置初始密码并再次确认，点击“创建成员账号”。
4. 查看成功提示中的账号，退出后使用新账号及刚设置的密码登录。

账号为 3–30 位字母、数字或下划线，按不区分大小写查重；学号 / 工号也必须唯一。密码为 8–64 位，至少包含一个英文字母和一个数字。已有成员资料编辑不会改变密码，目前没有重置密码界面。

演示模式只保存自定义密码的随机盐和 PBKDF2-SHA256 校验结果，不保存明文；这仍是浏览器内的演示校验，生产认证需要由后端实现。

### 借用与归还模块

```text
待审批 → 待发放 → 使用中 → 待确认归还 → 已归还
   ├→ 已拒绝
   └→ 已撤销（仅申请人）
```

1. `member` 在模块管理选择空闲模块，填写用途及预计归还时间后提交。
2. 切换 `manager`，在“借用与归还”通过申请，记录进入“待发放”，此时尚未占用模块。
3. 确认实物交付后点击“确认发放”，模块显示“使用中”。
4. 切回 `member` 申请归还，再由 `manager` 验收收到的实物。
5. 完好资产恢复空闲；损坏资产勾选后填写问题说明，自动进入维修。

发放时会再次检查库存；申请归还不会立即释放模块。当前只支持整单归还。“逾期”是根据预计归还时间计算的提示，不是额外的借用状态。

### 工作状态与请假

成员可自行设置“空闲”或“忙碌”。提交请假后，由有权限的老师或负责人审批；已通过的请假在有效时段覆盖工作状态为“请假”，结束后恢复原状态。“离线”为示例状态，尚未实现真实在线检测。

测试即时生效时，可将请假开始设在当前时间之前、结束设为未来；请假不能与已有待审批或已通过记录重叠。只有待审批申请可以由本人撤销。

### 比赛时间、流程与须知

老师或负责人在“比赛管理”新增比赛，填写报名时间、比赛时间、地点、负责人和参赛须知；通过“添加节点”维护初赛、决赛、答辩等安排。

日期须满足“报名开始 < 报名截止 ≤ 比赛开始 < 比赛结束”。每场比赛包含 1–20 个按时间排序的节点，支持赛后公布结果。普通成员只能查看；归档可恢复。节点到时仅表示计划时间已到，不代表实际完成。

目前不包含在线报名、组队提交、评分或附件上传。

## 数据保存与运行模式

| 模式 | 数据来源 | 适用范围 |
| --- | --- | --- |
| `mock`（默认） | 当前浏览器的 `localStorage`，登录身份保存在当前标签页的 `sessionStorage` | 本地体验、界面与业务流程验证 |
| `api` | 后端会话及 `/workspace` 聚合数据 | 后端实现接口后联调使用 |

演示数据键为 `xinzhan.lab.demo.v1`，登录会话键为 `xinzhan.lab.session.v1`。刷新页面保留演示修改，同源标签页可接收更新；同步保留正在编辑的弹窗与草稿，但几乎同时写入仍可能互相覆盖。

个人中心“恢复演示数据”在确认后覆盖当前浏览器的演示修改并退出登录。清除浏览器站点数据也会丢失本地记录。不同浏览器或设备不共享这些数据。

页面每 30 秒重新计算时间相关状态；这不是服务器轮询，关闭页面后不会继续提醒。详细限制见 [已知问题](TEST-REPORT.md#已知问题与后续工作)。

```sh
npm start       # 启动本地 HTTP 预览，需要 Python 3 且 4173 端口空闲
npm run check   # 运行全部 34 项自动化测试，需要 Node.js 20+
```

修改源码后刷新页面即可。首页按 `core → seed → ui → competitions → features → app` 顺序加载六个脚本；调整入口时需保持依赖顺序。项目不生成独立打包目录。

## 阿里云后端对接

在 [src/core.js](src/core.js) 中配置 `CONFIG`。后端完成 [API 契约](API.md) 的接口后，将 `mode` 改为 `api`，并设置实际 `API_BASE_URL`；同域反向代理可使用 `/api`。API 模式连接失败会明确报错，不会回退到演示数据。

服务器部署需上传 `index.html` 与整个 `src/`，由后端负责账号认证、权限、隐私字段裁剪和数据库事务。数据库连接信息与阿里云凭证仅保存在后端。目前仓库不包含真实云服务实现，GitHub 上传也不等同于阿里云部署。

## 常见问题

| 问题 | 处理方式 |
| --- | --- |
| 本地页面打不开 | 在项目目录启动预览服务，确认端口为 4173、终端仍运行 |
| 启动提示端口被占用 | 确认已有服务是否为本项目；换端口会使用独立演示数据 |
| 账号无法登录 | 检查大小写及账号是否启用；新建成员使用独立密码；默认账号只适用于 mock 模式 |
| 换浏览器或地址后数据消失 | 返回原浏览器及原协议、主机名、端口；本地数据不会自动迁移 |
| 审批通过但模块仍空闲 | 完成实物交付后点击“确认发放” |
| 找不到审批或新增按钮 | 对照角色权限；负责人仅能处理普通成员申请，所有人禁止自审批 |
| 比赛或请假状态与截图不同 | 示例按初始化时间生成，并随实际时间及操作变化；必要时恢复演示数据 |
| 想让多人跨设备共享数据 | 实现 API 并部署后端，前端本地存储不能完成跨设备同步 |
